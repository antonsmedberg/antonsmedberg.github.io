Subtl

Preparing for App Store release

A focused caption editor for iPhone. Import a video, transcribe the speech on your device, refine the words and styling, then save a captioned copy to Photos. No account or app server is required.

Role
Solo developer: design, code and tests
Stack
SwiftUI, SpeechAnalyzer, Foundation Models, App Intents, AVFoundation

Support site

What it does

You import a video from Photos or Files, and SpeechAnalyzer transcribes the speech on the phone. It handles English, Swedish and the other Nordic languages, as well as Spanish, German, French and Thai, wherever iOS offers them. In Studio you refine the words and choose one of five caption styles: Karaoke, Boxed, Clean, Pop or Typewriter. Then you save a captioned copy to Photos, or write SRT and WebVTT.

The app connects to Siri, Shortcuts and Spotlight through App Intents. A long export continues in the background with a Live Activity. The app itself is in English and Swedish.

What you see is what exports

Studio and the exported movie draw the same caption pages from the same glyph outlines.

A caption editor has two rendering paths that can drift apart: the interactive preview and the exported file. In Subtl, both draw from the same Core Text glyph outlines, so a word lands in the same place, weight and colour in both. Transcription runs in an actor under Swift 6.

A model that cannot change a word

Apple’s Foundation Models only suggest punctuation and titles. A validator turns down any answer that changes the words, and timing never comes from the model.

I also built Ask Subtl, an assistant that searches clips and transcripts through tool calling and proposes changes the user must confirm. It is not in 1.0 and comes back in version 1.1.

A library that survives a crash

A versioned index, journals for creations and removals, unreadable records set aside instead of overwritten, and seven days to undo a delete. The project catalogue turned out to need as much care as the renderer.

Built around the hinge

Subtl never asks which device it is on. It asks iOS where the reserved regions are and lays itself out around them. Open flat, the video and captions each take a side. Propped open like a laptop, the video sits above the hinge with the transcript below. Closed, the full editor fits the outer display.

Splitting is not always right, so a small function called usableFold decides. Beside the hinge, it returns the fold only if the video keeps at least 168 points and the captions at least 288. At large accessibility text sizes, Studio always uses one column.

What I cut

The moving Metal field behind Home kept drawing while nothing happened, so it went. So did a fake Dynamic Island that repeated the export’s progress while the caption panel already showed it. Version 1.0 also keeps a shorter list of spoken languages. Checking caption breaks and search in every language iOS offers was more than I can maintain.

Current state

A 1.0 release candidate. It is not on the App Store yet: export, accessibility and performance still need to be accepted on a physical device. The support site and privacy policy are live.
